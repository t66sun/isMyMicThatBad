# Adding a compiled filter

The engine processes mono f32 blocks at 48 kHz. Edit authored source in `src/native/src`; the Tauri workspace is generated by the [build scripts](../README.md#source-and-build).

1. Copy `template.rs` and implement `Filter::process`, `set_params` and any algorithmic delay in `latency()`. Allocate history/scratch buffers in the constructor; avoid allocation, blocking locks, disk access and logging during processing.
2. Add the type, display name, description, color and numeric ranges/defaults to `src/app/src/filters.json`. Rust validation and the editor share this catalog. Optional `summaryKeys` selects up to two card values; all parameters remain in the inspector.
3. Register the constructor in `Chain::new` in `dsp.rs`. The editor generates the card and controls from metadata.
4. Test through `Chain` in `tests/audio_pipeline.rs`: a known signal, state across blocks, independent instances and smooth parameter/bypass transitions.

The template's `amount_db` control uses 10 ms smoothing. To register a copy, append this definition to `filters.json`:

```json
{"type":"user-trim","name":"自定义滤镜","description":"可修改的滤镜模板。","color":"#75bfc7","parameters":[{"key":"amount_db","label":"强度","unit":"dB","min":-24,"max":12,"step":0.1,"default":0}]}
```

Add `"user-trim" => Box::new(crate::template::TemplateFilter::new(config.params["amount_db"]))` to the constructor match and rebuild. This is a compiled extension point; there is no runtime script/DLL loader.

Pitch/formant processing in `effects.rs` uses Signalsmith Stretch wrapper 0.1.3 with a 2048-frame window and 64-frame hop. Adjacent pitch/formant cards share analysis while retaining independent controls and bypass. Zero shifts use aligned dry audio. Declare the complete delay for compensation. The wrapper's formant-base setter incorrectly forwards to formant shift; retain default analysis.

## Hardware checks

Stop other audio senders and use an isolated portable copy. `isMyMicThatBad.exe --devices` lists endpoints; `--smoke 5` starts the physical microphone and VB-CABLE and performs a live filter edit. `--smoke 1800` is the optional 30-minute stability run.

After initializing the local Tauri workspace, run the opt-in latency test:

```powershell
cargo test --release --features custom-protocol --manifest-path src/app/src-tauri/Cargo.toml --test hardware_latency microphone_to_cable_p95_is_under_150ms -- --ignored --nocapture
```

Use native f32 / 48 kHz endpoints, monitoring off and a 5 ms buffer. Set `MIC_TEST_INPUT_ID` from `--devices` for repeatable comparisons. The calibration measures raw and frequency-zero/gain chains; silent or uncorrelated input is inconclusive, and chat-app buffering is excluded.

For the four new presets, export shared definitions with `node src/app/node_modules/tsx/dist/cli.mjs tests/export-presets.ts <absolute-json-path>`, set `MIC_TEST_PRESETS_FILE` to that path and run `new_presets_microphone_to_cable_p95_is_under_200ms` instead. It uses same-preset DSP references and source timestamps to retain both algorithmic and hardware delay, requires at least 20 matches and 80% coverage, and rejects application underruns/overflows. It does not establish long-term stability. Audio remains in memory.

With the same microphone and preset environment variables, run `female_preset_runs_without_underruns` for the 30-minute female-preset regression. It opens a CABLE Output reader, requires continuous delivery and zero application queue underruns/overflows, and records recoverable device notifications separately. Samples are drained in memory. `MIC_TEST_SECONDS` can shorten diagnostic runs to 10–1800 seconds, with 1800 as the default. The preset latency test also rejects any underruns. Run the opt-in `audio::tests::output_reader_quiet_tail_has_realtime_headroom` library test optimized to profile the output sinc callback with normal audio and tiny tails.
