# Domain Docs

## Layout

Single-context: `GLOSSARY.md` at the repo root and ADRs under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.
If they do not exist, proceed silently.
The `domain-modeling` skill creates them when terms or decisions are resolved.

## Vocabulary and decisions

Use glossary terms in issue titles, proposals, hypotheses, and test names.
If a needed concept is missing, reconsider the term or note the gap for `domain-modeling`.
Surface any conflict with an existing ADR explicitly, naming the ADR and the reason to revisit it.
