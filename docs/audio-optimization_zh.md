# 音频延迟后续

[English](audio-optimization.md) | 中文

合格目标：原始／零频移增益校准 p95 ≤150 ms，四个新预设 ≤200 ms。早先的 120 ms 和 80 ms 目标仍然延期。当前测量和限制见[用户指南](user-guide_zh.md#设备与缓冲)。对于 v0.4.0，用户明确接受超出这些延迟目标以换取稳定音频；当前测量不是延迟目标通过。

## 2026-11-06 资源竞争

最终 AI 清晰人声链在固定 CPU／CUDA 任务下连续运行 **1,800.03 秒**，应用欠载、溢出和记录丢失均为零，启动时的一次驱动通知此后没有增长。输入到 CABLE Output 的 p95 为 **836.46 ms**，114 个窗口中有 105 个达到相关分数 ≥0.5。条件为 RTX 2050、在 TANCHJIM 采集时钟注入语音、VB-CABLE、5 ms 应用缓冲、监听开启但物理输出写零。这是合成资源竞争证据，不是新的声学测量或游戏长测。原始结果位于 `20261106-022300-monitor-headroom/20261106-031123589-six-on-replay-1800s-1/`。

首次最终长测在确认变声音频后 386 ms 出现一次监听欠载，已提前停止。当时 AI 队列仍有约 400 ms 可播数据，DSP 块只耗时几十微秒。监听流原先在预填完成后才启动，首次回调一次取走五个 DSP 块，使随后一次 20 ms 生产间隔前的余量不足。现在两个渲染端都在采集前启动，让首次填充在实时队列就绪前获得静音。回放现场生产／监听顺序时，旧顺序产生一次欠载，新顺序为零；队列大小和声明延迟没有改变。中止记录继续作为失败保存在 `20261106-004820-game-reserve/soak-first-failure.json`，修复构建与鉴定位于 `20261106-022300-monitor-headroom/`。

线程预算筛选中的显存没有下降：两种预算下，PyTorch 峰值已分配显存均为 472.86 MiB，预留显存均为 632 MiB。这些分配器计数不包含其他进程和驱动分配。

最终长测的固定任务为每 19 ms 执行两次 2048 阶 FP32 矩阵乘法，以及按 100 ms 周期运行的八个 CPU 哈希进程。计入音频及其他应用后，CPU 占用中位数／p95 为 57.3%／78.6%，GPU 为 91%／100%，高于最初的中档目标。推理 p95／p99／最大耗时为 147.21／159.40／196.06 ms，桥接往返 p95 为 149.22 ms。AI 队列最低保有 10,816 帧，即 225.3 ms 可播音频。DSP p99／最大耗时为 0.296／2.607 ms，两个输出均无削顶采样。整卡显存中位数为 917 MiB、最大值为 926 MiB，包含竞争任务。最终二进制另行通过关闭监听的静音调参、重排、旁路和移除 AI 卡检查；全部测试进程均已退出。

启动修复后，女声和 AI 各三次 90 秒启动通过。空灵两次通过，第三次约 75 秒处出现六次欠载，影响主路和监听。连续三个 DSP 块耗时 25.38、27.29、22.82 ms，同窗整机 CPU 占用峰值达到 97.56%，该轮 GPU 中位占用为 93%。未记录线程 CPU 周期，因此尚未隔离调度等待和实际 DSP 计算耗时。这一饱和负载边界继续记为失败；最终长测仅继续验证已单独通过短测的 AI 链，不宣称全部预设稳定性通过。

当前 worker 将 PyTorch／OpenMP／FAISS 的 CPU 线程预算设为 2，保留 200 ms 输入块、Saisho 模型及索引、检索强度、音量包络混合和模型上下文。《Probably Stolen》运行期间，三组各 30 秒的配对探测中，worker 进程 CPU 时间分别减少 **53.6%、47.3%、46.9%**。这是进程 CPU 时间，不是整机占用或游戏帧率。GPU 合成区间和竞争任务完成时间没有一致改善。提高 CUDA 优先级和重叠音高提取均已淘汰，交付 worker 不包含这两项实验。最终固定随机种子的 30 秒探测得到 1,440,000 个采样，与四线程基线逐采样一致。

原 260 ms 回包余量未能承受游戏竞争：四线程实机短测四次中两次停机，双线程四次全部停机。首错均为 AI 输出队列耗尽，推理尖峰达到 369 ms，桥接额外耗时约 1～3 ms。用户明确允许增加 100～200 ms 延迟后，回包余量调整为 **420 ms**，加上输入积累后声明的 AI 延迟为 **620 ms**。可控管道回归在新余量下能承受 370 ms 回包，在旧余量下失败；耗尽后静音及首错保留断言继续启用。若推理持续慢于每 200 ms 一块，仍可能耗尽队列。

620 ms 配置下，三组四／双线程交替实机短测均持续输出 90 秒。在相同固定背景任务下，原四线程／460 ms 对照的 p95 为 681.16 ms，双线程／620 ms 候选为 830.04～841.25 ms，实测增加 **149～160 ms**。条件为 RTX 2050、在 TANCHJIM-OLA II DSP 采集时钟注入合成语音、VB-CABLE、5 ms 应用缓冲、监听开启但耳机写零。参考为注入输入，不是麦克风声学实收录音。各对照均满足至少 20 个窗口、相关分数 ≥0.5、匹配率 ≥80%。这些测量发生在游戏退出后，不代表游戏共存或帧率验收。

最初校准的背景任务在 GPU 频率从约 1515 MHz 降至 735 MHz 后变重，占用升至约 95%；女声随后一轮出现 **22 次欠载**，保留为失败的性能边界测试。空灵及增加余量后的 AI 短测承受住了该配置。必须同时报告固定工作量和实际持续占用，不能用短暂校准证明 GPU 始终为 60%。

证据：`research/audio-acceptance/artifacts/20261105-214600-voice-quality/` 保存游戏对照与试听控制，`20261106-001140-rvc-overlap/` 保存淘汰的重叠实验，`20261106-004820-game-reserve/` 保存授权后的余量测试、固定负载、原始匹配窗口和最终鉴定。`tests/resource_worker.py` 测量本地 worker CPU 时间与采样输出，`tests/resource_load.py` 创建固定 CPU／CUDA 任务，`tests/resource_monitor.py` 单独记录整机占用。这些工具均不播放声音。

## 2026-11-05 RVC 实测

RTX 2050 使用 Saisho 模型及索引时，原六卡链开监听的五次启动曾有四次因 AI 输出队列耗尽而停机。复用预热 CUDA 图后，五次实麦短测都持续输出了变声音频。其中四次从确认出声起达到 90 秒，一次为 89.14 秒。同一原配置还单独连续运行了 1,800.05 秒，稳态计数无增长。测量使用 TANCHJIM-OLA II DSP 麦克风和耳机、VB-CABLE、5 ms 应用缓冲和 520 ms 算法预留。从麦克风实收语音到 CABLE Output 的 p95 为 733.31 ms。

最终配置收集 200 ms 输入，给推理回包保留 260 ms。使用相同设备、监听和应用缓冲，清晰人声预设在 TANCHJIM 采集时钟上送入已知波形，耳机写零，连续运行了 1,800.04 秒。到 CABLE Output 的 p95 为 656.44 ms，113 个窗口中有 106 个匹配。应用欠载和溢出始终为零，启动时的一次驱动通知此后没有增加。400 ms 方案出现首块回包迟到并停机，已淘汰。

清晰人声预设在同一静音链路各跑 91 秒时，520 ms 预留的 p95 为 **721.13 ms**，460 ms 预留为 **661.10 ms**，分别匹配 207/219 和 204/219 个窗口。最终配置有五次独立启动从确认出声起均达到 90 秒，另一次因线缆初始脉冲提前计时，实际为 89.38 秒，单独保留。

等响盲听选中了清晰人声。在相同 RVC 输出上，相对干净高通参考的波形差 RMS 从 63.61% 降到 14.74%。共振峰所需的合成长度改在模型载入时预热，独立测量多用约六秒。重排卡片时复用同一模型的建流耗时从 248.6 ms 降至 6.5 ms。实时调参、重排、全局原音切换和移除 AI 卡各阶段均向 CABLE Output 持续交付音频。

原始配置、2 ms 匹配窗口、逐块计时、计数变化和失败记录保存在 `research/audio-acceptance/artifacts/20261105-000235-voice-fix/`，原始停机证据位于 `research/audio-acceptance/artifacts/20261104-224546-six-card/`。

## 2026-11-05 轻声对照

同输入离线对照定位到，女声和空灵声的 −50 dB 噪声门首先压低了轻声。以移除噪声门的同一预设为参考，超过 6 dB、持续至少 20 ms 的衰减累计分别为 1,680 ms 和 1,650 ms。只将门限降到 −60 dB 后，两者都降为 20 ms，并消除了持续一秒的轻声冷起音静音。语音标记在处理前由输入确定，输出按声明的 DSP 延迟对齐。音高、共振峰目标和噪声门时间参数不变。读取实际导出预设的起音／字尾回归在旧参数下失败，在新参数下通过。

底噪代价已单独测量：稳定的 −65 dB 噪声仍会关闭噪声门，−60～−55 dB 噪声则可能通过。输入为 −55 dB 噪声时，女声和空灵的稳态输出分别为 −57.65 dB、−62.57 dB，旧预设在此时为静音。两组 15.75 秒试听各采用整段固定增益，等响至 −23 LUFS。用户认为两组差别都不明显，因此尚未证明自然度改善。证据位于 `research/audio-acceptance/artifacts/20261105-214600-voice-quality/`，包括 `controls`、`gate-candidates`、`noise-controls` 和试听反馈记录。

## 需要保留的约束

- 合格配置：Intel 麦克风、VB-CABLE 3072 samples / 48 kHz、5 ms 应用缓冲、关闭监听。仅线缆 p95 测得 56.29 ms；该边界与完整路径不同，因此不能通过相减隔离应用延迟。
- 固定 10 ms WASAPI 输出缓冲请求未降低完整路径延迟，已撤回。将输出预留从两个设备周期降到一个是导致 19 次调试运行和 16 次优化运行欠载，已撤回。当前源码保留三个标称输出周期（受队列容量限制），启动时额外保留一个周期；实际 WASAPI 回调可能超过标称周期。在降低该预留前重新鉴定延迟。
- 已启用 CPAL 实时调度和 DSP worker 优先级。回调唤醒 worker。离线 DSP 余量不能证明回调截止时间或端到端延迟。
- 变换后的声音需要同预设处理参考，用源时间戳减去声明的 DSP 延迟。直接比较原始波形不可靠；安静或低相关运行不是通过证据。

## 当前稳定性回归

输出队列现在保存完整 DSP 块，监听预热为 sinc 输入历史留出空间。输出重采样前将低于 1e-20 的不可听样本替换为零：优化后的三秒极小尾音探测从约 0.372 s 降到 0.007 s，不改变可听样本或样本时序。共享预设 DSP 余量测试也覆盖安静尾音。

在上述合格麦克风／线缆配置下，三次连续的优化 10 秒女声预设启动均通过，持续向 CABLE Output 读取器交付，应用欠载／溢出为零。随后运行在最后一条 1230 秒状态记录后按用户要求停止，应用队列计数同样为零；这不是完整的 30 分钟通过。可恢复的驱动通知仍可观察到。完整路径 p95 未重新测量，额外预留可能增加延迟。

## 固定链 RVC 故障取证

使用优化构建和保存的六卡配置。在项目工具链终端中执行 `cargo test --release --features custom-protocol --manifest-path src/app/src-tauri/Cargo.toml --test hardware_latency --no-run` 构建观察器，将命令输出的测试程序路径传给脚本。每批试验先建立新的带日期证据目录。

```powershell
./tests/Run-ChainEvidence.ps1 -TestExe $testExe -SessionPath $session -AiRoot $preparedAi -EvidenceDirectory $evidence -StimulusWav $speech -SpeakerId $physicalSpeaker -CableReaderId $cableOutput -Scenario six-on -Repeats 5 -Seconds 90
```

分别以 `six-off`、`rvc` 和 `dsp` 运行匹配对照，以 `digital` 运行扬声器回环。测试语音会从扬声器播放。脚本在生成的构建目标目录中准备独立运行时，每轮单独保存配置、首错状态、可用的 GPU 日志、逐块计时、限幅前峰值和各端点能量。麦克风音频只在内存中处理。比较延迟时保持设备路径、电平、缓冲和监听状态一致。`tests/summarize_chain_evidence.py` 可以汇总原始结果。应用在故障停止后保留队列计数，直到再次启动或主动停止。上一轮 worker 日志位于 `ai/worker.previous.log`。

静音测试使用同一个观察器，构建时启用 `--features custom-protocol,acceptance-replay`。在上述命令加上 `-SilentReplay`，省略 `-SpeakerId`。该模式在真实 48 kHz 麦克风回调内用 WAV 代替采样，分别记录采集时钟与 CABLE Output。耳机监听正常处理，最终向物理端点写零，时间线保留写零前的电平。测量房间声学链或耳机端点本身时使用有声模式。

离线音质对照使用 `tests/chain_quality.py prepare` 和本地 48 kHz 单声道 PCM16 语音生成素材。将新素材及命令输出的时长传入 `tests/ai_inference.py`，指定 `--output-directory` 和 `--float-output`。把六卡配置和导出的四个预设作为 `session.json`、`presets.json` 复制到音质目录。将 `MIC_TEST_QUALITY_DIR` 指向该目录，运行优化版 audio_pipeline 中显式忽略的 `quality_probe::render_matching_inputs_at_each_card`，再执行 `tests/chain_quality.py summarize`。汇总记录造成波形变化的级别及随机试听片段的实测响度，人工听评与客观指标分开记录。
