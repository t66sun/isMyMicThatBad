# Working rules

isMyMicThatBad is a portable Windows x64 voice changer: a React/Tauri editor over a Rust audio engine, with an optional isolated RVC worker. The microphone feeds bounded WASAPI queues, an ordered mono DSP chain and CABLE Input; other applications capture CABLE Output. These rules bind every agent and human change.

## Hard rules

1. **Edit authored source only.** `src/app/src` is the editor; `src/native` is the native engine and build configuration. `src/app/src-tauri` is generated by `scripts/Initialize-Native.ps1` and ignored. Vendor runtime files copied beside it are local prerequisites, not repository content.
2. **Keep the audio callback real-time safe.** `Filter::process` allocates nothing, takes no blocking lock and performs no disk access, logging or unbounded work. Allocate history and scratch buffers in constructors, and return declared algorithmic delay from `latency()`. Audio is mono f32 at 48 kHz in 256-frame blocks.
3. **Keep one filter catalog.** Types, labels, ranges and defaults live in `src/app/src/filters.json`; Rust validates the catalog and the editor renders it. Register processors in `Chain::new` in `dsp.rs`. There is no runtime plugin loader.
4. **Treat evidence as read-only.** `research/` logs and records, `release/` packages and acceptance hashes are historical. New measurements go into a new dated artifact. Failed or partial runs stay visible and are never reported as passes.
5. **Match claims to measurements.** State device, buffer, monitoring state and reference for every latency result. Accepted limitations stay labelled accepted; deferred work stays deferred. AI inference runs locally, audio never leaves the machine, and AI failure stops output instead of falling back silently.
6. **Let validation gate delivery.** `./scripts/Build.ps1 -ChecksOnly` runs Rust tests, editor tests and TypeScript checks. `./scripts/Package.ps1` additionally requires a clean committed tree and a matching `research/audio-acceptance/artifacts/delivery-acceptance.json`. Never bypass, weaken or skip either gate.
7. **Carry a regression assertion with each behavior change.** The check fails when the change is reverted. A check that cannot run is reported as not run, never as passed.
8. **Stay under 1000 lines.** Split along existing seams instead of growing a file past the limit. `tests/hardware_latency.rs` (1348 lines) predates this rule and shrinks when next substantively edited.
9. **No AI attribution.** Commits, pull requests, issues, reviews and generated artifacts carry the user's authorship only: no agent names, co-author trailers or "generated with" lines.

## Layout

| Path | Contents |
| --- | --- |
| `src/app/` | React editor, shared filter catalog (`src/filters.json`), Vite/TypeScript configuration and editor tests |
| `src/native/` | Authored Rust engine: streams and worker (`audio.rs`), DSP (`dsp.rs`, `effects.rs`, `graph.rs`), clock (`clock.rs`), settings (`settings.rs`), window and tray (`main.rs`), AI worker (`ai.rs`, `ai/`) |
| `scripts/` | Build, native initialization, packaging and toolchain scripts |
| `tests/` | Rust integration tests, editor regressions and PowerShell/native acceptance harnesses |
| `docs/` | Stable documentation, including `docs/agents/` operational docs |
| `research/` | Ignored research, acceptance evidence and local toolchains under `research/<topic>/artifacts/` |
| `release/` | Ignored local portable packages and delivery manifests |

Root files: `README.md` (Chinese mirror `docs/README_zh.md`), `AGENTS.md`, `TODO.md` (live work ledger), `VERSION`, `codegraph.json`, `.gitignore` and `.gitattributes`.

`src/app/src-tauri/` is generated and ignored. `research/`, `release/`, dependency trees, build output and vendor runtimes stay out of Git.

## Documentation

- Every maintained doc exists twice: the English original and its Chinese mirror with the `_zh` suffix. Create, edit, move, rename and delete both in the same change; English is authoritative. `AGENTS.md` stays English-only.
- The root keeps `README.md`; its mirror is `docs/README_zh.md`. Both carry the language switch.
- Portable packages ship the Chinese user guide as `README.md` and the Chinese latency note as `AUDIO-OPTIMIZATION.md`. `scripts/Package.ps1` reads `docs/user-guide_zh.md` and `docs/audio-optimization_zh.md`; keep those paths and their relative links valid.
- `docs/handoff.md` records the latest delivery state. Keep its mirror in step when it changes.

## CodeGraph

`.codegraph/` is a local index and is ignored. `codegraph.json` covers `src/`, `tests/` and `scripts/`. Use `codegraph_explore` before grep or reading code to locate symbols and trace callers.

## Git workflow

- Never commit directly to `master`; every change, however small, lives on a branch. Only the primary agent commits and operates on remotes; subagents return changes plus verification evidence.
- One branch changes one behavior; keep restructuring separate from tuning. State the changed behavior in the pull request and commit messages, following the existing `type: imperative summary` style or Conventional Commits.
- Stage explicit first-party paths; inspect `git diff --cached --name-only` and keep `research/`, `release/`, generated `src/app/src-tauri/`, dependencies and vendor files out. Preserve other people's staged and unstaged work.
- Commit after applicable validation passes. Do not commit read-only work, unchanged content or failing changes, and do not commit unrelated files.
- At phase end the primary agent reviews and verifies each open pull request, merges it into `master`, and pushes under the authorization in the governance block. Tags and Releases still need explicit authorization. Stop on remote or tag conflicts; never force-push or rewrite published history.

## Issue tracker

Requests and specs live in GitHub Issues for `t66sun/isMyMicThatBad`; `gh` resolves the repository from `origin`. Pull requests are not a request surface. Read `docs/agents/issue-tracker.md` before creating, reading, linking or closing a ticket, and `docs/agents/triage-labels.md` before applying a label. The five canonical labels are `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human` and `wontfix`.

## Domain docs

Read `docs/agents/domain.md` before exploring domain concepts or decisions. It defines the single-context layout: `GLOSSARY.md` at the repository root and ADRs under `docs/adr/`.

## Git and documentation rules

- Stay on the current branch; inspect HEAD, staged, unstaged, and untracked changes at the start of each task.
- Only the primary agent commits and operates on remotes; subagents deliver changes and verification evidence.
- Keep commits limited to files authored for this project. Exclude `research/`, all `tauri/` and `src-tauri/` directories (including `src/app/src-tauri/`), cloned external repositories, and vendored third-party files, even when they are already tracked.
- Stage explicit first-party file paths. Before committing, inspect `git diff --cached --name-only` and verify that no excluded paths are staged. For an explicitly requested tracking cleanup, excluded paths may appear only as deletions; retain their local files.
- Automatically commit actual changes after applicable validation passes. Do not commit read-only work, unchanged content, or changes that fail validation.
- Commit only task changes, preserving others' work and the original staging state. Clarify ownership when mixed changes cannot be reliably separated. Include both old-path deletions and new-path additions in migration commits.
- Follow the existing commit style; otherwise use Conventional Commits.
- Commit messages must detail the affected files/components and concrete changes; create local documentation only when essential, such as README.md or AGENTS.md.
- Pushes and tags require explicit authorization; existing authorization remains valid within its scope. A push alone does not create a tag. Authorization to publish to GitHub covers the required push, tag, and Release operations.
- Report and stop on remote or tag conflicts. Do not force-push, overwrite, or delete published tags.
- Read and maintain `TODO.md` during project work, mark items complete only after verification, adjust affected items when implementation is blocked or results miss expectations, and when all items are complete, clear the entire file and remind the user to request a rewrite.
